**CF1 — The controller introduces a confound the v2 memo does not analyze: the specificity arm's symmetry.** The BF1 fix adds threshold adaptation driven by *outcome feedback*. But outcome feedback responds to realized errors regardless of their cause. In the memory arm, retrieval corruption produces errors; the controller will respond to them exactly as it responds to mirror-induced errors — adapting the threshold, moving the operating point. The v2 memo argues the candidate arm's compensation is structurally limited (global threshold cannot fix per-query misranking); it never asks whether the *memory* arm's compensation is limited in the same way. If memory corruption produces errors the mirror *correctly assigns low confidence to*, threshold adaptation works well there — risk stays in band, specificity passes, fine. But if memory corruption produces *confidently wrong* retrievals (plausible: a corrupted store returning coherent-but-stale content), the mirror misses them, the controller saturates, and regulation error rises in the memory arm — **failing specificity for a reason that is arguably the system working honestly**. The v2 design has made the specificity arm's prediction theory-dependent in a way v1's pure-gating design was not. **Condition:** the pre-registration must state the predicted memory-arm mechanism explicitly (mirror detects memory-induced degradation → confidence drops on affected queries → abstention absorbs them within the coverage budget) and must pre-commit to how a confidently-wrong-retrieval failure is classified: candidate failure, instrument failure, or a documented L8 boundary condition. Deciding this after seeing data is the goalpost-move the program exists to forbid.

**CF2 — C_min and η are named as Principal decisions but arrive with no decision procedure, and they jointly determine the test's outcome.** The coverage floor and adaptation gain are not tuning details; the dose-response's existence depends on where C_min sits relative to the noise-flippable mass near the threshold, and η bounds how much compensation is available. The v2 memo hands these to Rebecca as "construct-determining constants" with no derivation, which converts the Principal gate into a dartboard. An uninformed choice here produces either a floor so low the system abstains its way out (flat curve, L8 fails, wrongly) or so high the test is trivially passed (risk rises at any noise, wrongly). **Condition:** the candidate-blind power analysis already required under BF4 must be extended to a two-dimensional sensitivity map over (C_min, η) on synthetic profiles, delivered to the Principal *with* the gate items, so her ruling selects from characterized options rather than blessing numbers. This is work before the gate, not after.

**CF3 — The delayed outcome-feedback channel changes the system under test for L7 and L10 as well, and the v2 memo is silent on it.** Per-window ground-truth feedback is new information flowing into the candidate during operation. L10's abstention bars and L7's mirror calibration were specified against a system without this channel. If the channel exists only in L8 batteries, the M4 candidate is two different systems across its own laws — an integration-law smell (L14–L17 territory) and a gift to a hostile reviewer. If it exists everywhere, L7/L10 specs need reconciliation. **Condition:** ARCHITECT must disposition this explicitly — recommended: the feedback channel is a harness-provided environment feature present in all M4 batteries, with L7/L10 specs re-checked against its presence and the check documented. One paragraph, but a mandatory one.
