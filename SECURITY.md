# Security Policy

## Reporting a vulnerability

Do not disclose credentials, exploitable vulnerabilities, private machine information, or sensitive artifact contents in a public issue.

Use GitHub's private vulnerability reporting feature for this repository when available. If private reporting is not enabled, open a public issue containing no sensitive details and request a private contact channel.

Include only the minimum information required to reproduce the problem safely. Never include a complete secret value; redact it to a short prefix and identify the affected provider and location.

## Scope

Security reports may include:

- exposed credentials or personal information;
- unsafe artifact or log publication;
- dependency vulnerabilities with a credible impact path;
- code-execution, path-traversal, or unsafe deserialization issues;
- workflow or repository-permission weaknesses.

Historical scientific disagreements and result interpretation belong in ordinary issues, not security reports.
